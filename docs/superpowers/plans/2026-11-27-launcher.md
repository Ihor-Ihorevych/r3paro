# r3paro Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cross-platform Avalonia launcher that lets the player choose the HP3 game folder, validates it, remembers it, and starts `hp3` on it.

**Architecture:** One Avalonia app with a single `MainViewModel`; all I/O behind small injected services (validator, settings, launcher, folder picker). A separate xUnit project tests services and the view model with fakes.

**Tech Stack:** .NET 11 (`net11.0`), Avalonia (latest stable 11.x/12.x from NuGet), CommunityToolkit.Mvvm, Microsoft.Extensions.DependencyInjection, xUnit.

**Spec:** `docs/superpowers/specs/2026-11-27-launcher-design.md`

## Global Constraints

- Target framework `net11.0` for both projects; nullable enabled.
- Folder: `apps/launcher/` with `R3paro.Launcher.slnx` (or `.sln`), `R3paro.Launcher/`, `R3paro.Launcher.Tests/`.
- Valid game folder = exists, `System` dir, `System/Core.u`, `Maps` dir, writable (`Save/` created if missing). Name matching case-insensitive.
- Engine binary `hp3.exe` on Windows, `hp3` elsewhere, next to the launcher (`AppContext.BaseDirectory`) unless `EnginePath` is set.
- `hp3` is started with the game folder as its only argument (use `ProcessStartInfo.ArgumentList`), working dir = engine dir.
- Early failure = non-zero exit within 5 s; report the last 20 stderr lines.
- Settings JSON at `<ApplicationData>/r3paro/launcher.json`.
- The view model never references Avalonia types.
- Do not touch the Rust workspace; do not run `cargo fmt`.

## Review Focus

1. Game folder path with spaces or non-ASCII characters → engine receives it intact as one argument (Task 3 test).
2. Engine binary missing → Play shows "Engine not found: <path>" and does not throw (Task 3 + Task 4 tests).
3. Saved folder deleted or moved since last run → window opens with the reason it is invalid, Play disabled (Task 4 test).
4. Corrupt or empty `launcher.json` → defaults, no crash (Task 2 test).
5. Play clicked twice quickly → only one launch (Task 4 test: `PlayCommand.CanExecute` false while running).

### Task 3: GameLauncher

**Files:**
- Create: `R3paro.Launcher/Services/IGameLauncher.cs`, `Services/GameLauncher.cs`
- Test: `R3paro.Launcher.Tests/GameLauncherTests.cs`

**Interfaces:**
- Consumes: `ISettingsStore` (for `EnginePath`).
- Produces: `public sealed record LaunchResult(bool Started, string? Error);`
  `public interface IGameLauncher { Task<LaunchResult> LaunchAsync(string gameFolder, CancellationToken ct = default); }`
  `public static string GameLauncher.ResolveEnginePath(string baseDir, string? configured, bool isWindows)`
  `public static string GameLauncher.Tail(string text, int lines)`
  Constructor `GameLauncher(ISettingsStore settings, string baseDir, TimeSpan earlyExitWindow)`; DI passes `AppContext.BaseDirectory`, `TimeSpan.FromSeconds(5)`.

- [ ] **Step 1: Failing tests:**
  - `Resolve_uses_configured_when_set` → returns configured path.
  - `Resolve_windows` → `Path.Combine(baseDir, "hp3.exe")`; `Resolve_unix` → `Path.Combine(baseDir, "hp3")`.
  - `Tail_returns_last_lines` (25 lines in, last 20 out, joined by `\n`).
  - `Missing_engine` → `Started == false`, `Error == $"Engine not found: {path}"`.
  - `Early_failure_reports_stderr`: engine = a script written to temp (`.cmd` on Windows: `echo boom 1>&2` + `exit /b 3`; `sh` script with `chmod +x` elsewhere) → `Started == false`, `Error` contains `boom`.
  - `Argument_passed_intact`: script writes its first argument to a file; launch with folder `"<temp>/HP3 Ü dir"` → file content equals that path; result `Started == true` when script exits 0 (exit code 0 within the window counts as started).
  - `Long_running_counts_as_started`: script sleeps 3 s, window = 500 ms → `Started == true` within ~1 s.
- [ ] **Step 2: Run** → FAIL.
- [ ] **Step 3: Implement.** `ProcessStartInfo` with `ArgumentList.Add(gameFolder)`, `WorkingDirectory = Path.GetDirectoryName(engine)`, `RedirectStandardError = true`, `UseShellExecute = false`; read stderr asynchronously into a buffer; `await Task.WhenAny(process.WaitForExitAsync(ct), Task.Delay(window, ct))`; exited with non-zero → `new(false, Tail(stderr, 20))`, else `new(true, null)`. Catch `Win32Exception` on start → `new(false, e.Message)`. After the window keep draining stderr so the pipe never blocks the game.
- [ ] **Step 4: Run** → PASS.
- [ ] **Step 5: Commit** `feat(launcher): start hp3 and report early failures`
